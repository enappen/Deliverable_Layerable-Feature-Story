Element Content purpose Normal-flow baseline Chosen technique and why Containing block / stacking context Fallback or disengagement Required test
aside (.story-guide) The aside is used as a navigation guide for the featured story. Block The sticky position is used so the aside navigation can travel downward with the user as they read the document to remain an available usable resource. The containing block is the div container (.article-container) in column 1 with a column width of 14rem. A margin-left of 4rem is applied to accommodate the blockquote element. A z-index of 2 is assigned to keep it above the article column. The fallback for the sticky position is relative. If sticky is not supported or disengaged, the aside element will not move back into the normal document flow but have no moved position. To test the fallback, I commented out the support at-rule for the aside element. I expected the sticky element to remain static at the top left and function normally (scrolling with the user to the end of its container). I observed the aside element remained in its initial position and then scroll through the container when comments were removed. No changes were needed.
Figcaption The figcaption provides additional context to the images purpose and its connection to the featured story. Inline The relative position is used to adjust the caption position from it's original location to move it up over the image. The max-width is set to 640px (the max-width of the image its overlapping) and a min-width of 0 so it will remain responsive with the image. The top property lifts the caption enough so when the text wraps, the bottom of the caption background lines up with the bottom of the image. The containing block is a figure (.feature-figure) and is after the image element in the contained figure. If the figcaption element is disengaged or unavailable due to a users browser setting, the figcaption element falls back to a static positioned element right below the image. Since the figcaption wouldn't be over an image when disengaged, I made the background color opaque and left no margin on top. This give the caption a similar illusion of being attached to the image. To test the fall back works, I commented out the supports at-rule for the figcaption. I expected the top of the figcaption background color to line up to the bottom of the image and maintain the same width as the image. I observed that the figcaption behaved as expected and no changes were needed.
Image (.shape-portrait) The image, with class shape-portrait, is helpful for providing a visual to various types of fiber that connect to the section 2 text in the featured story. Block The image, with the class shape-portrait, is clipped using the clip-path property with the value circle(7.6rem). Relative units are used to maintain consistent clipping mask. The image has a float property with value inline-start to have the image anchor to the left of text. The shape-outside creates a rounded boundary box for the text to fall along. The shape-margin of 0.5rem add to the newly defined boundary box. The containing block is the section element, with class section-two. The stacking context for smaller viewports proceeds in the order of heading, image, then text. The fallback for the clip-path and shape-outline is the border-radius property that is set to 50%. It keeps the image round even when the clip path doesn't work. The shapes outline returns to a block style format, with the round image on the left and text on the right. To test the fallback, I commented out the support at-rule for the shape-portrait class regarding the clipping and special margins. I expected the image to remain in a circular shape and the test to be on the right in block form. I observed the image stayed round and the text behaved as expected. No changes are needed.
Span (.issue-badge) The purpose is to display the genre/theme of the article. For this website, it is the Friday's Fiber Feature special. Block The badge is positioned with absolute to keep it anchored to its parent in the top right corner. The containing block is the header element. The stacking context is the eyebrow, badge, heading, then introduction paragraph. The fallback for this is applying a position of relative to keep it near its starting position moved slightly up to have better spacing between the eyebrow and heading on smaller viewports to avoid unintended overlap. To test the fallback, I shrunk the viewport to less than 360px. I expected the span badge to fall below the eyebrow and have no overlap. I observed the span badge behaved as intended. No changes were needed.
